openDNA · unit tests

Every test, what goes in and what must come out

For each automated test of the DNA editor: why it matters, its inputs, the output it expects, what that answer is checked against, how much a pass is worth, and its result in the last run. Tests are grouped by file, one file per area. Use the filters to review one area at a time.

Reading a test

Many tests are topical: one test function holds several sections, and each row of its table is one section or case, in the order the test runs them. A test passes only when every row holds.

Why it matters
One sentence: what would break unnoticed for a user if the test did not exist. If you cannot agree with it, the test is a candidate for removal.
Input
What the test feeds in: sequences (bases are coloured A C G T), parameters or files from demo/. The suite has no UI tests: nothing drives a window.
Expected output
What the test asserts: exact coordinates, values, texts, or agreement with another program.
Checked against
hand-computed: worked out on paper and written in the test. independent implementation: another program, mostly Biopython, computes the answer. in-test reference model: a plain model written inside the test, such as the sequence as a Python string. property/invariant: a rule that must always hold, such as undo restoring the original. round-trip/self-consistency: save then reload gives the same thing. GUI state: what the window shows. smoke: only that nothing crashes.
Strength
Strong: exact values or an independent check, edge cases included. Adequate: the main behaviour, some edges or exact values missing. Weak: a clearly wrong program could still pass.
Review notes
What the reviewer found could be checked better. Changed by the audit says what was fixed or added in November 2026.
Not reviewed
A test without a written description. Its docstring and every assert line are shown as the code has them.

Rebuilding this page

QT_QPA_PLATFORM=offscreen python -m pytest tests -q --junitxml=junit.xml
(cd core && cargo test > ../cargo.txt 2>&1)
python scripts/test_report.py --junit junit.xml --cargo cargo.txt

The descriptions live in docs/test-report/tests.json; the script writes the Markdown pages and this page from them and from the run.
