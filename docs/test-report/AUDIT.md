## Gaps and proposed tests (3 of 237 tests)

Tests that do not fully prove what they claim: what a bug could slip past, and a test that would catch it.

### `tests/test_checkup.py::test_origins_and_prediction_thresholds`

- The ColE1-group note is asserted on a construct whose five origins are random filler named by label, so nothing distinguishes a note driven by the origin families from one driven by the number of rep_origin features.

**Proposed test:** Add a positive control beside the noise bound, in the same test. (1) Recall: st = C.Strand(filler(200, 41) + PROMOTER + filler(200, 42), 1, False), with PROMOTER the module-level consensus sigma-70 string 'TTGACAATTAATCATCCGGCTCGTATAATGTGTGGAA' (-35 at offset 0, -10 TATAAT at offset 25, so the -10 box sits at base 200 + 25 = 225 and the filler is T-free, hence nothing else can score); assert len(C.predict_promoters(st, 10)) == 1 and that the hit's interval covers 200..237. Same for terminators: st2 = C.Strand(filler(200, 43) + T1 + filler(200, 44), 1, False) with the rrnB T1 string already in the file; assert len(C.predict_terminators(st2, 18)) == 1 and abs(hit.a - 200) <= 3. (2) Turn the noise bound into a measured rate: plant 20 copies of PROMOTER at known bases inside the 50 000 random bases, assert at least 18 of the 20 planted windows hold a hit and that hits outside every planted window are still <= 8. This catches the proven mutation (predictors returning []) and any threshold change that silences them, which the present bounds welcome.

### `tests/test_feedback.py::test_log_file_and_error_hooks`

- 'one dialog per distinct error (main and worker threads)': because the test injects show_dialog, _handle_exception takes the `_state['dialog'] is not None` shortcut and calls the dialog directly IN the worker thread. The production path (no injected dialog, worker thread -> Qt signal bridge -> main thread) is never exercised, so a dead or disconnected bridge means worker errors never show a dialog.
- Still open: Needs a running Qt event loop (the worker-thread signal path), out of scope for a suite without UI tests.

**Proposed test:** Set up with show_dialog=None but patch feedback._default_dialog with a recorder that also records threading.current_thread() (and patch opener/clipboard). Raise in a worker thread, join, then QCoreApplication.processEvents() (or QTest.qWait(50)). Assert one call, summary 'ValueError: from a worker', and the recorded thread is threading.main_thread(). Catches F3 and a bridge that calls the dialog off the GUI thread.

### `tests/test_file_assoc.py::test_startup_question_decision_table`

- 'asks once' and 'don't ask again wins' are tested only with flags the test writes into the ini by hand; the box's buttons (yes_button, later_button, never_button), which are what write those flags, are never clicked, so the app could ask at every start (the role's 'nag users at every start', 'ignore don't ask again').
- Still open: Clicking the question's buttons needs a real QMessageBox, out of scope for a suite without UI tests.

**Proposed test:** frozen=True, windows=True, fresh ini, empty FakeRegistry: box = F.ask_at_startup(None, ini, reg, EXE, windows=True, frozen=True); assert box; box.later_button.click(); assert ini.value('asked') == 'true' and should_ask(...) is None and box not in F._open_boxes. New ini: box.never_button.click(); reload with F.open_settings(path) and assert _flag dont_ask true and should_ask None. New ini: box.yes_button.click() (register_now with the fake registry; patch QMessageBox notice if it blocks) and assert is_registered_for_current_exe(reg, EXE) and asked true. Catches A1.
